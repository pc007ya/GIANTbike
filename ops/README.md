# GIANTbike 供應商個人帳號｜Spark 登錄制

本候選版用管理員核准的 Firestore 登記取代自訂 Auth claims。**不用 Cloud Shell、服務帳號金鑰、Cloud Functions 或 Blaze。** 沿用 giantbike-a0c4f 的原資料庫和 vendor ID；不搬既有供應商記錄或變更 GitHub Pages 網域。

## 開戶與撤銷

1. Firebase Console 的 Authentication → Users 以承辦人的公司信箱新增個人帳戶。每人獨立；由管理員在當地產生高強度、不同的初始密碼，不傳給承辦人、不在網站或聊天輸入。可用本網站登入頁「設定／重設密碼」發送 Firebase 正式連結，讓承辦人自設密碼。新登入如要求信箱驗證，從登入頁「重寄驗證信」完成後再登入。不要把驗證或重設網址貼到公開紀錄。
2. 只從上述新建 Firebase 帳號核對 UID 與信箱。新版 GIANTbike 以現有管理員 Google 登入，在「管理中心 → 供應商 → 供應商個人帳號」登記這組 UID、公司信箱以及原廠商 ID。只有管理員能登記。已登記 UID 的信箱與公司不能改寫。新進、轉任、離職依核實的不同個人帳號處理。
3. 承辦人先以已驗證公司信箱及密碼登入。到「我的帳號」選定並連結 Google 帳號，再輸入原密碼確認。兩種方式使用同一 UID；Google 的同信箱自動關聯本身不授權，帳號衝突不合併。Google 登入經批准後仍要通過同 UID 的公司登記。
4. 停用在管理中心以 UID 查詢，核對後操作「停用權限」。停用的登記對後續伺服器操作立即生效，即使原 Firebase token 還未過期。線上 UI 收到拒絕後清除本次會話；無法撤回停用前合法下載或客戶端已複製的資料。必要時再由擁有者在 Firebase 停用其 Auth 帳戶，**不刪除舊紀錄**。

## 用量

訪客讀 GitHub Pages 靜態公開目錄，不讀 Firestore。供應商私有讀寫規則會檢查一份身分登記，Google 登入還比對一份綁定文件；按 Firestore 規則依附讀取計入用量。新增與停用是一次小型寫入；不新增伺服器、帳單方案或長期雙寫。不保證剩餘免費額度；以主控台實際讀寫量為準。

## 正式切換

- 核對正確 Console 專案及預設 Firestore，保留原 Google 管理員；確認 Pages 網域已授權。現有廣泛規則尚未收緊前**不要啟用 Email/Password**。先安排切換窗口、可信的資料保存和兩家核准測試信箱，不自動邀請真實客戶。Spark 無法執行需付費的受管匯出；如需驗收前額外備份，先由擁有者用既有授權方案保存，不升級。
- 以控制台 Firestore Rules 發布此候選現有的 firestore.rules，確認正式規則及其生效。這會關閉舊匿名配合公司的共用碼寫入；未開通的新承辦人暫停提交。禁止為回退恢復舊寬鬆規則。核對後才啟用 Email/Password、發布同一候選的 GitHub Pages，保留公開目錄和原圖，不部署 Firebase Hosting 或未使用的 Cloud Storage。
- 新版 Google 管理員登入後先「發布供應商目錄與專案」，新視圖分開，不改原主檔。以兩家核准的資料驗證 UID、歸屬、個人信箱、Google 登入、歷史與停用。既有僅存在本機的記錄不會被搬移或刪除；要保留的由管理者另核對。
- 新版關閉前端直寫 Google 試算表。既有試算表與 Apps Script 部署不會因 Pages 自動修改；若另有公開設定，須由擁有者針對實際部署獨立處置。正式站未知狀態下，僅保留公開看圖和查詢的安全回退。
