# GIANTbike 供應商專案分層（私有候選，不能直接部署）

沿用 Canyon 的管理員分配模式，不沿用只擋畫面的做法。清單與詳情，包括直接以網址開啟的測試、治具、設備、圖片和 3D 檔，應由後端按當前身分與專案分配裁切；未分配的 CIC 應為空，不套用完整預設目錄。

本候選只有純函式與合成資料測試，尚未串接正式 Firestore 和檔案服務。不能發布此分支。沒有切換 Pages 或主分支，沒有複製正式資料。實作下一步：
1. 公開登入殼只載入無業務資料的介面和身份元件，移除「返回公開治具目錄」及所有靜態目錄／圖資預載。登入後讀取經 Rules 保護的資料視圖，不把目錄寫到持久本機快取。
2. 將 scopedVendorCatalog 的結果按既有分配寫入每廠獨立投影（連同完整版本標記，防止讀到一半更新）；擋供應商讀共用完整目錄。保留管理員完整主檔及現有廠商資料。評估分包和實際 Firestore 讀取量。
3. 檔案服務由服務端核對 Firebase 身分＋當前有效分配後才供應，不能直接公開靜態路徑、公開下載網址或複用暫存。先核准託管位置，測無登入、A/B 交叉，空 CIC、分配收回和深層連結。不能為了上線啟用新的付費服務或變更現有帳號。
